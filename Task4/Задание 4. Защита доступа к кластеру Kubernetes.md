Задание 4. Защита доступа к кластеру Kubernetes

1. Поднимите пустой Minikube.
2. Определите все роли и их полномочия при работе с Kubernetes.
3. Подготовьте скрипты для создания пользователей.
4. Подготовьте скрипты, чтобы создать роли.
5. Подготовьте скрипты, чтобы связать пользователей с ролями.

# Инструкция запуска
## 1. Запустить Minikube:
```shell
minikube start
```

## 2. Дать права файлам на запуск
```shell
chmod +x 1-create-users.sh 2-create-roles.sh 3-create-bindings.sh
```

## 3. Выполнить скрипты п порядку
```shell
./1-create-users.sh
./2-create-roles.sh
./3-create-bindings.sh
```

### Группа "viewers"
#### только просмотр ресурсов кластера
- Могут просматривать все ресурсы кластера
- Не могут ничего изменять, создавать или удалять
- Идеально для аналитиков, менеджеров, новых сотрудников

### Группа "operators" 
#### настройка кластера (но не полный доступ)
- Могут создавать/удалять неймспейсы
- Могут управлять PersistentVolumes и StorageClasses
- Могут настраивать сетевые политики
- Могут управлять приложениями внутри неймспейсов
- Нет доступа к секретам и RBAC на уровне кластера

### Привилегированные группы:
- security - доступ к секретам
- auditors - полный аудит кластера

### Принципы безопасности, примененные в решении:
- Принцип наименьших привилегий - каждая группа имеет только необходимые права
- Разделение обязанностей - операторы не имеют доступа к секретам, security не имеет доступа к настройке кластера
- Защита от эскалации привилегий - нет прав на управление ClusterRoles, ClusterRoleBindings для непроверенных групп
- Аудит - отдельная группа для мониторинга действий

### таблица ролей и групп

| Группа	   | Роль/ClusterRole     | 	Полномочия	                                                           | Пример пользователя |
|-----------|----------------------|------------------------------------------------------------------------|---------------------|
| viewers   | 	cluster-viewer      | 	Только просмотр ресурсов кластера  	                                  | viewer1             |
| operators | 	cluster-operator    | 	Настройка кластера: неймспейсы, PV, StorageClasses, сетевые политики	 | operator1           |
| operators | 	namespace-operator  | 	Настройка приложений в неймспейсах	                                   | operator1           |
| auditors  | 	cluster-auditor     | 	Аудит всех ресурсов кластера 	                                        | auditor1            |
| security  | 	security-specialist | 	Управление секретами в security неймспейсе                            | 	security1          |

### Для тестирования

- Для тестирования доступа viewer1 (только просмотр):
```shell
 kubectl config set-credentials viewer1 --client-certificate=users/viewer1.crt --client-key=users/viewer1.key
 kubectl config set-context viewer1-context --cluster=minikube --user=viewer1
 kubectl --context=viewer1-context get pods --all-namespaces
```

- Для тестирования доступа operator1 (настройка кластера):
```shell
 kubectl config set-credentials operator1 --client-certificate=users/operator1.crt --client-key=users/operator1.key
 kubectl config set-context operator1-context --cluster=minikube --user=operator1
 kubectl --context=operator1-context create namespace test-namespace
 kubectl --context=operator1-context get storageclasses
```

- Просмотр всех ClusterRoles и Roles
```shell
kubectl get clusterroles
kubectl get roles --all-namespaces
```

- Просмотр привязок
```shell
kubectl get clusterrolebindings
kubectl get rolebindings --all-namespaces
```

- Проверка доступа конкретного пользователя
```shell
kubectl auth can-i --as=operator1 get pods -n development
kubectl auth can-i --as=operator1 create pods -n development
```
